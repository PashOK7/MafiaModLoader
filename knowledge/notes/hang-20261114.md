## Controlled native Ogg deadlock, then cooperative shutdown

After the owner rejected a four-hour route replay, the investigation moved to bounded native
teardown tests. Eight muted native Ogg streams survived 100 stop/reopen cycles; twelve different-scene
save loads (490/495 alternating) also returned normally. Neither negative stress result identifies
the historical hang. Save loads are not the exact CHANGE_MISSION actor/car carry-over path.

Static reads in BOTH LS3DF builds located an unsafe cancellation mechanism: IShow::Close calls
TerminateThread on its Ogg decoder, then ov_clear invokes close_func/dtaClose on the main thread.
The decoder's ov_read/read_func/dtaRead uses the SAME rw_data global critical section as dtaClose.
Terminating a thread does not release a critical section it owns:
https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminatethread

race_probe.py made that timing window deterministic in owner test PID 9596. It identified the
native IShow's exact decoder TID, verified its process, and suspended it only after confirming it
owned rw_data+EC6C. Normal music.stop killed that thread (exit code 0), left the critical-section
owner equal to its dead TID 24764, and blocked the main thread in IShow::Close -> ov_clear ->
close_func -> dtaClose -> RtlEnterCriticalSection. Archive-close-race.json records the before/after
lock and thread states. This took seconds, not a four-hour play session. The recorder captured
three real hang dumps/where replies (Hang_9596_20261114T090527Z_0/1/2, 536410 bytes each). PID 9596
was deliberately left stalled for capture, then force-closed by exact copy/PID. This is an INDUCED
native deadlock with a proven mechanism, NOT proof that PID 21004 died for the same reason.

host/ogg.cpp now replaces only the infinite Ogg notification loop and chains IShow::Close. A
per-IShow stop event wakes the replacement worker; Close joins it after any current ORIGINAL
native refill completes, then native Stop/ov_clear/decoder cleanup runs. The joined worker/event
are removed from the native TerminateThread branch and both handles are closed. No forced unlock,
kill timeout, audio disable, backend change, or gain/timing nudge. The original native refill,
DirectSound backend, flags and EOF handling remain; native notify thresholds differ (1.0: 22,
1.2: 11). Close-before-first-thread-entry uses the same retained stop state. Non-Ogg native cleanup
and the existing FFmpeg hook chain are retained.

Addresses/ABI/layouts were read in both builds and added to game_build.h/check_builds.py, with
Rust tables regenerated. sound.compat.ogg_shutdown exposes read-only start/exit/join/state/failure
counts. Source and installed ASI/PDB preimages are in build/ogg-shutdown-fix-20261114/before.

Real-game regression in BOTH labs: suspend the verified reader while it owns the archive lock,
request normal stop on the game thread, check that the reader is STILL ALIVE and close waits,
resume, check normal exit code 0, successful close, no orphan owner, responsive game thread, join
count increment. All pass. Thirty-two immediate opens/closes per build also leave no retained
state growth; the existing sound allocation/source-buffer checks pass. game-tests-2.log: 12 checks
passed per build, zero failed. Initial test's final diagnostic query failed because MCP injects
timeout_ms into params whereas sound.compat rejects all parameters; the actual lock/exit assertions
passed. The test now queries with {} and passes; the metadata mismatch is documented, not hidden.

Historical cause remains unestablished without a dump of the original PID 21004. A fix for this
confirmed native teardown defect must not be presented as a fix for all observed crashes/hangs.
